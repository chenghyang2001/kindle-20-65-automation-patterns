## Step 4：思考你自己的專案該怎麼分層

### 練習

假設你正在開發一個 Node.js + React 全端應用，把以下規範分層：

```
你的規範清單：
- Commit 訊息格式（Conventional Commits）
- React 元件用函式型（不用 class）
- API endpoint 命名規則（kebab-case）
- 不允許 console.log 留在 Production 程式碼
- 自動化 PR 審查流程
- 資料庫連線字串在 DB_URL 環境變數
- TypeScript strict mode 啟用
- 測試覆蓋率 > 80%
```

## 本課重點

```
三層的本質是「載入時機」不同：

  第一層（CLAUDE.md）
    → 永遠掛著，每次對話都在
    → 只放 AI 在整個專案裡「隨時隨地」必須知道的事
    → 越精煉越好（一個字都是成本）

  第二層（rules/）
    → 碰到特定檔案類型才載入
    → TypeScript 規則 = 不寫 .ts 時完全不存在
    → 0 token 成本直到真正需要

  第三層（skills/）
    → 明確呼叫或 AI 判斷情境吻合才喚醒
    → 自動化流程、特定任務的完整步驟
    → 平常絕對不消耗 context

核心原則：
  把 AI 的注意力空間當成寶貴資源管理
  越不常用的規則，就讓它越晚進入 AI 視野
```
