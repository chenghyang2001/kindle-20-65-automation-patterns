# 實作前檢查清單

**實作任務**：$ARGUMENTS

逐一驗證以下 5 個項目，每項以 PASS / FAIL / SKIP 作答。

## C1：重複實作檢查

- 執行 `grep -r "RelatedClassName\|relatedFunctionName" --include="*.{ts,py,go}" src/`
- 確認程式碼庫中不存在等價的功能
- 若既有程式碼可以擴充（不需要新實作）則判 FAIL

## C2：架構合規檢查

- 檢視 `CLAUDE.md` 中的架構約束
- 確認沒有違反依賴方向、分層隔離或命名慣例

## C3：官方文件檢查

- 查閱將使用的函式庫或框架的官方文件
- 確認預計使用的 API 在目前版本中有效

## C4：OSS 參考檢查

- 檢查是否有開源專案實作過類似的模式
- 評估能否避免重複造輪子

## C5：根本原因確認檢查

- Bug 修復或效能改善：是否已找出根本原因？
- 新功能：是否已確認使用者的真實需求？

---

## 分數計算

- PASS 數量：N / 5
- ≥ 90%（4 / 5 以上）→ 可以放心開始實作
- ≤ 60%（2 / 5 以下）→ 停下來重新調查

針對每個 FAIL 或 SKIP 項目，列出原因與補救方式。
