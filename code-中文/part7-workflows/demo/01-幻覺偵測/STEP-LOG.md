## Step 2：辨識以下 AI 假回覆中的紅旗

### 模擬情境

你問 AI：「用 Python requests 做 OAuth2 驗證怎麼做？」

AI 回覆如下：

```
使用 requests-oauthlib 這個套件大概可以節省 40% 的程式碼量。
你只需要呼叫 OAuth2Session.fetch_token()，
傳入 token_url 和 client_secret 就可以了。
這個方法在 requests 2.0 版開始支援，效能通常比手動實作快兩倍。
另外，你也可以用 client.get_token() 這個更簡潔的語法。
```

- RF2：「節省 40% 的程式碼量」、「快兩倍」— 沒有根據的效能數字


### 預期結果

- 若 AI 真的能給出可點開的 URL → 值得信任
- 若 AI 給出無法驗證的 URL 或含糊帶過 → 幻覺警報

## 本課重點

| 工具 | 用途 | 對抗的問題 |
|------|------|-----------|
| 7 個紅旗訊號 | 人類審查者辨識可疑回答 | AI 過度樂觀、資料不確定 |
| 4 個驗證提問 | 逼 AI 提供可查證的實體證據 | 無從確認的幻覺資訊 |
| 「我相信這是...」 | 自動觸發防禦機制 | 自信掩期、損碩其詞 |

> 幻覺不是能力缺陷，它是 LLM 的結構性特質。
> 比起說「你答案是錯的」，說「請到文件中查證」能得到更準確的修正。
