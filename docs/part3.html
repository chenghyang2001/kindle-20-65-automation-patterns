6 個內建 Agent 解剖
點擊卡片查看每個 agent 的職責與適用場景。
🔍 Explore
探索型
快速搜尋程式碼庫：找檔案、找符號、回答「X 在哪裡定義」。唯讀模式，不修改任何檔案。
🗺️ Plan
規劃型
在實作前設計步驟清單、評估架構 trade-off、識別關鍵檔案。只輸出計畫，不自己動手。
🔨 Executor
實作型
埋頭實作個別 spec 任務，寫乾淨且通過測試的程式碼，遵守專案 conventions。
👀 Code Reviewer
審查型
對程式碼做 adversarial review，找 bug、安全漏洞、邏輯錯誤，列 MUST_FIX 與 NICE_TO_HAVE。
🐛 Debug Expert
除錯型
追根究柢找 bug，用二分搜尋法、假設-驗證流程系統性診斷問題，不找到根因不罷休。
✅ Verify App
驗證型
端對端驗證應用程式可運作，可用 Puppeteer 截圖確認 UI、執行 smoke test。
Explore — 用途：大範圍 codebase 搜尋、按 pattern 找檔、快速回答「X 在哪」。
不該做：不寫程式只找檔、不做深度架構分析。
觸發時機：「找所有用到 fetchRoom 的地方」「哪個檔案定義了 AuthMiddleware？」
Agent({ subagent_type: "Explore", prompt: "找所有呼叫 pymysql.connect 的 .py 檔，列出路徑和行號" })
模型選擇矩陣
正確的模型選擇可節省 60-80% 的 token 成本。
任務類型推薦模型理由
檔案探索 / 搜尋 / log 查詢Haiku只需讀取、速度優先，推理能力不是關鍵
格式審查 / Pattern matchingHaiku規則性強，Haiku 已足夠
Bug 修復 / 一般實作Sonnet平衡能力與成本，大多數任務的最佳選擇
安全稽核 / 架構設計Sonnet需要較強推理，但不需要 Opus 等級
大規模重構 / 複雜多步驟Inherit繼承主 Claude 模型，保持一致性
極複雜推理 / 關鍵決策Opus最高能力，但成本也最高，謹慎使用
# 探索型 agent 指定 Haiku — 省 60-80% token Agent({ subagent_type: "Explore", model: "haiku", prompt: "搜尋 code/ 目錄下所有 .sh 檔，列出檔名和第一行" })
反理由化行為對照表
當 AI 說出以下借口時，就是在迴避任務。正確做法是直接執行並回報阻礙。
AI 說的話真正的意思正確應對
「檔案太大」
懶得讀
用 Read 只讀需要的範圍
「測試太複雜」
不想修測試
先修測試，再實作
「與現有程式碼不相容」
沒把握改
改了，再另行回報相容性問題
「擔心有副作用」
不想改
最小化改動，文件化副作用
「有更好的做法」
想改指示
照指示執行，結尾建議替代方案
「發生錯誤了」
想停止
分析錯誤，嘗試解法，再回報
串聯審查流水線
PR 審查或功能完成後，按以下順序串聯 reviewer，每個只做一件事，Context 乾淨，判斷更準。
Spec Compliance
Reviewer → Code Quality
Reviewer → Security
Reviewer → API Reviewer
