Headless 三種傳入模式
在 CI 環境（無 TTY）執行 Claude 時，有三種方式傳入 prompt。
-p Flag
stdin 管道
Heredoc
-p Flag — 最常用，prompt 直接作為參數傳入。
  • ✅ 簡單直觀
  • ✅ 適合短 prompt（< 500 字）
  • ⚠️ 長 prompt 建議改用 stdin
claude -p "審查 code/ 目錄下的所有 .sh 檔案，找出安全漏洞" \ --dangerously-skip-permissions \ --output-format json
stdin 管道 — 用 echo 或 cat 把 prompt 通過管道傳給 Claude。
  • ✅ 適合多行、含特殊字元的 prompt
  • ✅ 可傳入動態內容（如 diff 結果）
  • ✅ CI 中最靈活的方式
PR_DIFF=$(git diff main...HEAD) echo "審查這個 PR 的改動： $PR_DIFF 輸出 APPROVE 或 REQUEST_CHANGES，附原因。" | claude \ --dangerously-skip-permissions \ --output-format text
Heredoc — 用 bash heredoc 傳入多行 prompt，支援變數展開。
  • ✅ 最可讀，適合複雜的多行 prompt
  • ✅ 可混合靜態文字和動態變數
  • ⚠️ 注意 Git Bash 的 heredoc 換行符問題
claude --dangerously-skip-permissions <<EOF 請審查以下 PR，PR 編號：$PR_NUMBER 改動內容： $PR_DIFF 判斷結準： - 有硬編碼路徑 → REQUEST_CHANGES - 有 SQL 注入風險 → REQUEST_CHANGES - 其他 → APPROVE 最後一行輸出 Verdict: APPROVE 或 Verdict: REQUEST_CHANGES EOF
Auto-pilot PR 流程
PR 開啟後全自動審查 → merge 或 auto-fix → 通知人工。
PR 開啟
→
review.sh 執行
→
Claude 審查
→
Verdict 解析
APPROVE
→ gh pr merge --squash --auto
（等 CI checks 通過後合併）
REQUEST_CHANGES
→ auto-fix-pr.sh
→ Claude 自動修正 code/
→ push → 觸發下一輪
⚠️ auto-fix 次數 ≥ 2 → 加 label needs-human-review + 通知
# Verdict 解析 — 用 tail -10 防誤判 VERDICT=$(echo "$REVIEW" | tail -10 | grep -oE 'Verdict[：:]\s*(APPROVE|REQUEST_CHANGES)') if echo "$VERDICT" | grep -q "APPROVE"; then gh pr merge --squash --auto elif echo "$VERDICT" | grep -q "REQUEST_CHANGES"; then bash auto-fix-pr.sh fi
5 個常見 CI 陷阱
實際踩過的陷阱，避開這些就能省下大量除錯時間。
陷阱 1：GITHUB_TOKEN push 不觸發 Workflow
症狀：auto-fix push 後 PR review workflow 不再觸發
✓ 修法：設 GH_PAT secret，用 PAT push 才能觸發後續 workflow
陷阱 2：set -e + command substitution
症狀：RESULT=$(claude -p ...) 在 set -e 下，claude 非零退出 → shell 直接終止
✓ 修法：用 if ! RESULT=$(claude -p ...); then 模式
陷阱 3：無 TTY 必須加 flag
症狀：CI 環境 Claude 卡在互動提示，job 超時
✓ 修法：加 --dangerously-skip-permissions（CI 專用，本機不需要）
陷阱 4：--output-format json 雙層包裝
症狀：PR 留言顯示原始 JSON 結構而非 markdown
✓ 修法：prompt 末尾加「輸出 markdown，不需要 JSON 包裝」
陷阱 5：Verdict grep 誤判
症狀：review 內文若引用含「APPROVE」的文字，grep 誤觸發 auto-merge
✓ 修法：echo "$REVIEW" | tail -10 | grep -qE "Verdict[：:]\s*APPROVE"
