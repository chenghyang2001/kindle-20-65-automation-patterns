Context 三層架構
點擊 Tab 了解每層的設計原則與適用場景。
🔵 Layer 1 — 永遠需要 (Always-on)
放在 CLAUDE.md 最頂部，每次 session 都自動載入。適合：全域規則、禁止操作（如 MySQL 唯讀）、語言偏好、Git 工作流。

原則：少即是多。放太多內容反而稀釋重要規則。只放「如果 Claude 不知道，每次都會犯錯」的內容。
# CLAUDE.md 頂部 — Always-on context ## 鐵律 - AWS RDS MySQL（zap_api）只能 SELECT，絕對不可修改 - commit message 使用繁體中文 - 不使用 --no-verify
🟢 Layer 2 — 條件需要 (Conditional)
用 @instructions/xxx.md 語法引用，只在相關任務時才被讀取。適合：框架規範、資料庫設計原則、部署流程、特定模組的開發規則。

好處：模組化 → 可以針對不同專案組合不同規則，不會讓 CLAUDE.md 越來越臃腫。
# CLAUDE.md 中段 — Conditional context @instructions/tech-stack.md # 前端技術規範 @instructions/code-quality.md # 程式碼品質原則 @instructions/dev-workflow.md # 開發工作流
🟣 Layer 3 — 隨需呼叫 (On-demand)
Skills（/skill-name）和 Sub-agent，只在需要時才觸發。不佔用日常 context，但功能隨時可用。適合：分析任務、特定操作流程、一次性的複雜工作流。

設計哲學：把 context 留給真正需要的資訊，其餘的讓使用者明確呼叫。
# 隨需呼叫 — Skills /confidence-check # 實作前信心清單 /orchestrate # 動態任務編排 /analyze-patterns # 日誌模式分析
CLAUDE.md 模組化設計
點擊卡片展開每個模組的說明與範例。
@instructions/no-hardcoded-paths.md
▼
絕對不可出現 C:\Users\<name>\ 等硬編碼路徑。必須使用可攜式寫法：Python 用 Path.home()，Shell 用 $HOME，Windows 用 %USERPROFILE%。

原因：專案在多台 PC 間同步，硬編碼路徑會導致跨機器執行失敗。
@instructions/code-quality.md
▼
包含 10 個原則：錯誤處理（try/except）、測試同時生成、樣板範本、程式碼風格、鷹架式開發、Windows 特殊注意、防禦性開發、安全性（SQL 注入 / XSS）、重構與效能、資料庫操作。
@instructions/dev-workflow.md
▼
11 個工作流原則：主動套用進階提示詞技巧、規格先行（> 50 行就寫 spec）、分解為獨立步驟、摘要檢查點、上下文接續、對話分支探索、全端開發 Checklist、文件維護、技術債審查、DB Schema 設計流程、Git 工作流。
@instructions/writer-qa-iron-rule.md
▼
最嚴格的模組：凡是建立或修改 .py/.js/.ts 等 17 個副檔名，主 Claude 禁止直接 Write/Edit，必須依序派 code-writer → code-qa → code-reviewer 三個 sub-agent。防幻覺 + 防自證 + 防技術債。
