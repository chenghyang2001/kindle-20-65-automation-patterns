# Claude Code CI/CD 自動化實戰教學

> **對象**：剛進職場的軟體工程師。
> 假設你會用 AI 對話寫程式、懂 Git / 測試 / 基本 CLI，但還沒接觸過「無人值守的自動化流程（CI/CD）」。
> 這份教材教你把「愛聊天的 AI 助理」，改造成 CI pipeline 裡**沉默、安全、可被機器調度的自主節點**。
> 所有範例老師都實際跑過，下面的 headless 輸出是真實呼叫的結果。

---

## 寫在前面：把萬能鑰匙交給裝潢師傅之前

想像你請了一位技術頂尖的裝潢師傅來翻修房子，給了他一把萬能鑰匙，講了大概方向就出門了。聽起來很理想——但你絕對不希望：

- 凌晨三點接到電話，只為了問「客廳能不能用電鑽」
- 一個月後收到幾百萬的帳單，只因為他覺得「把整棟樓拆掉重建比較快」

這幾乎就是我們把 AI 放進軟體開發流程時最真實的寫照。

我們平常用 AI，想到的都是一個**對話方塊**——你輸入指令，它給你回應，像個有問必答的助理。但這份教材（出自《Claude Code in Production》第四章）探討的是完全不同的領域：**無人值守的伺服器環境**。在這裡，沒有人類工程師能坐著按「確認」鍵。

核心任務：**讓 AI 助理閉上嘴巴，變成 pipeline 裡默默工作的自動化流水線員工。**

# 第一部分：拔掉對話框（Headless Mode）

自動化的第一步，是啟動**無頭模式（Headless Mode）**。關鍵參數是 `-p`（或 `--print`）。

加上它之後，Claude 會：

1. 默默在背景處理你的提示詞
2. 自己判斷並完成必要的工具呼叫
3. 把結果印到 **stdout（標準輸出）**
4. 直接退出，**不停下來問東問西**
5. 成功回傳退出碼 **0**，出錯回傳**非 0**

這完全符合 Unix 命令列工具的運作期待——其他腳本可以直接「按退出碼」判斷這一步成功還是失敗。

## 老師的真實實跑

我實際跑了一個 headless 呼叫（讓 AI 數 `code/part2-hooks/` 有幾個 .sh 檔）：

```bash
claude -p "How many .sh files are in code/part2-hooks/?" \
  --allowedTools "Glob" --max-turns 3 \
  --output-format json < /dev/null
```

退出碼 **0**，輸出的 JSON 裡 `result` 欄位就是純答案 `"9"`——**沒有「好的，為您分析一下」這種客套話**。這正是 CI 要的：機器能直接接手處理的乾淨輸出。

# 第二部分：講機器聽得懂的話（JSON 結構化輸出）

人類喜歡看排版優雅、有前言後語的回答。但對下游要接手的腳本來說，這些客套話是災難——讓 bash 去解析自然語言，後續邏輯很容易崩潰。

解法：加上 `--output-format json`，強制結構化輸出。

## 它的威力不只是「把文字包進括號」

JSON 輸出同時提供一層豐富的 **metadata（後設資料）**。看老師實跑得到的真實 JSON（節錄關鍵欄位）：

```json
{
  "result": "9",
  "is_error": false,
  "num_turns": 2,
  "total_cost_usd": 1.5403,
  "session_id": "f058f9ea-111d-4e50-b312-5d1b8c6ba02f",
  "duration_ms": 11342
}
```

每個欄位對 CI 都有用：

| 欄位 | 用途 |
|------|------|
| `result` | 純答案，下游直接用 |
| **`is_error`** | 最重要！下游用 `jq '.is_error'` 直接判斷，是 `true` 就亮紅燈中斷，不用寫複雜正則去找「抱歉」「失敗」字眼 |
| `total_cost_usd` | 這次花多少錢（成本監控）|
| `num_turns` | 經過幾個推論回合 |
| `session_id` | 之後可用 `--resume` 接續 |

> **下游程式碼只需要：** `jq -r '.is_error'` 抓一個欄位，就知道成敗。機器對機器的精準度，完全不在同一個層次。

## 更嚴格：`--json-schema`

你還能用 `--json-schema` 定義一份「超級嚴格的填空表」，強制 AI 回傳的 JSON 必須包含特定欄位（例如「受影響檔案的陣列」「安全風險等級的數字」）。格式不對，AI 就等於沒交作業——把防禦性程式設計的負擔，從人類身上徹底卸下。

## 💡 順帶一課：這次呼叫花了 $1.54

老師實跑的那次 headless 呼叫，`total_cost_usd` 顯示 **$1.54**——只是「數個檔案」而已！為什麼這麼貴？因為環境用的是最強最貴的 **Opus** 模型 + 首次建立快取。

> 這正是「殺雞用牛刀」——數檔案這種瑣事該用便宜 19 倍的 **Haiku**（`--model haiku`）。
> 而 JSON 裡的 `total_cost_usd` 欄位，就是讓 pipeline 能即時監控、抓出這種浪費的關鍵。

# 第三部分：三道防爆衝護欄（約法三章）

光是 `-p` 讓 AI 安靜還不夠——你還是怕它亂搞。CI 環境有三個不可或缺的護欄：

| 護欄 | 參數 | 防什麼 | 裝潢師傅比喻 |
|------|------|--------|-------------|
| **工具白名單** | `--allowedTools "Read,Glob"` | 沒人能即時批准，預先發白名單 | 「你可以用電鑽，別再打電話問我」 |
| **回合上限** | `--max-turns 20~30` | AI 陷入死循環，一直思考嘗試失敗 | 「最多讓你試 30 次」 |
| **預算上限** | `--max-budget-usd 2` | 收到百萬帳單 | 「兩塊錢一到，管它做完沒，立刻拔插頭」 |

這三道一起設，你在設定自動化流程時才能安心。

# 第四部分：日常應用——PR 審查與自動 Commit

## AI 自動審查 PR（`pr-review.yml`）

每當有人開新 PR，GitHub Actions 自動啟動 Claude 出審。怎麼把程式碼餵給它？

```bash
gh pr diff <PR編號> | claude -p "審查這段 diff，找出潛在 bug 與安全漏洞"
```

用 pipe 把 `gh pr diff` 的差異**只送變動的部分**給 Claude，讓它把分析結果當 PR 留言發出來。就像多了一個永遠不知疲倦的資深同事先幫你看過一遍。

### 關鍵最佳實踐：Prompt 版本控制

不要把審查指令用字串寫死在腳本裡，而是用 `--append-system-prompt-file` 讀取一個**外部 prompt 檔案**，並納入 Git 版本控制。

> 這是 AI 工程化的里程碑——你的團隊可以追蹤「審查指令怎麼演進」：今天因為踩了坑加一條「特別注意資料庫連線超時」，明天又改了另一條規則，全部在 Git 歷史一目瞭然。

## AI 自動寫 Commit Message（`auto-commit.sh`）

趕進度時，commit 訊息永遠是 `fixed stuff`、`update`——對以後查問題的人是悲劇。讓 AI 來寫：

```bash
git diff --cached | claude -p "依 Conventional Commits 規範產生 commit 訊息" \
  --allowedTools "Bash(git status *),Bash(git diff *),Bash(git commit *)"
```

它會自動生成像 `fix(auth): 解決 token 重新整理時的競爭條件` 這種專業描述。

# 第五部分：安全——別讓 AI 刪了你的專案

前面一直讓 AI 跑 `git diff`、看歷史，這代表它在執行 **bash 指令**。如果在 CI 伺服器給它終端機權限，它會不會哪天幻覺一個 `rm -rf` 把專案刪了？

這是很多企業不敢把 AI 放進核心流程的主因。解法有兩層：

## 解法一：工具白名單絕對限縮

不要給 AI 全功能的 bash，而是用白名單給**極度精準的限定工具**：

```bash
--allowedTools "Bash(git diff *),Bash(git log *)"
```

底層系統只放行這兩個 git 查詢指令。AI 若想刪檔或寫檔，系統直接拒絕並報錯——它**完全觸碰不到實體檔案系統**。

> 這給它的不是萬能鑰匙，而是**一副只能看不能摸的望遠鏡**。

再配合把 diff 結果直接用 **stdin** 餵給 AI（不讓它自己去翻檔案），更安全也更快。

## 解法二：plan mode 硬限制（軟限制 vs 硬限制）

這是理解 AI 工程的重要概念：

| | 軟限制 | 硬限制 |
|---|--------|--------|
| 做法 | 在 prompt 裡寫「請只分析不要修改」 | `--permission-mode plan` |
| 可靠性 | AI 是機率模型，**有幻覺忽略指示的機率** | 系統層級，啟動就是純唯讀分析器，底層拔掉修改能力 |
| 比喻 | 口頭警告師傅「不要敲牆」，他心情不好還是可能砸下去 | 物理上拔掉他的錘子 |

範例 `security-scan.yml` 就用 `claude --permission-mode plan -p "..."` 做安全掃描——**不論 AI 怎麼幻覺都無法突破的物理防線**。

# 第六部分：自動修復的封閉迴圈（Verify-Fix-Verify）

最刺激的應用：讓 AI 從「旁邊看戲的檢查員」變成「實際動刀的外科醫生」。當自動化測試失敗時（`auto-fix.yml`）：

```
測試失敗 → 把 test-output.txt 餵給 Claude → AI 分析並修改原始碼
   → AI 在自己的內部迴圈用 bash 再次跑測試 → 確認變綠燈才結束
```

關鍵：AI **不是瞎猜改幾行就交卷**，它會自己反覆確認「我改的真的讓錯誤消失了嗎」，確定測試通過才結束。

## 兩個攸關生死的安全機制

**① 只開 PR，絕不直接 push 主分支**
修復成功後，AI 的最終動作只能是**開一個新 PR**。這確保人類工程師永遠是最後一道把關防線。

**② commit 訊息必須加 `[skip ci]` / SKIP ACTIONS 標籤** ⚠️

這是一個漏掉就萬劫不復的細節。想想看：

> AI 開 PR → 推送程式碼 → CI 偵測到新程式碼 → 自動觸發測試 → 又失敗 → 又呼叫 AI 修 → 又開 PR → **無限連鎖觸發**，直到 API 額度被徹底燒光。

加上 SKIP ACTIONS 標籤，就是告訴 CI 平台「這是 AI 自動生成的提交，別為它觸發後續自動化」——一個短標籤直接切斷災難迴圈。這是在生產環境實戰過才得出的寶貴經驗。

# 第七部分：複雜流程編排——記憶熱插拔與平行宇宙

## Session 延續（`multi-step-ci.sh`）

把流程拆成多步驟（步驟一分析、步驟二寫測試、步驟三開 PR）時，怎麼確保 AI 在步驟二還記得步驟一讀過什麼？

如果只把步驟一的幾句 JSON 文字丟給步驟二，它讀過幾百行程式碼的上下文就全流失了。解法是用 `session_id`：

```bash
# Step 1：捕捉 session_id
SESSION=$(claude -p "分析所有 hook" --output-format json | jq -r '.session_id')
# Step 2：用 --resume 接續，不需重讀
claude -p "根據剛才的分析，列出 3 個改進點" --resume "$SESSION"
```

`--resume` 不只讀對話記錄，而是讓新進程**完整接管上一個的大腦狀態**——思考脈絡、快取的檔案內容全部繼承。像把 AI 的記憶體**熱插拔**到下一個任務。

## 平行宇宙（`parallel-review.sh` + Git Worktrees）

如果一個 PR 要同時做資安掃描 + 生成 API 文件，排隊做太慢；但同時啟動兩個 AI 讀寫同一個資料夾，會檔案衝突。

解法：`git worktree` 在硬碟上建立**完全獨立的實體資料夾**（連到同一個 repo，但有自己的工作目錄）：

```bash
claude -p "資安掃描" ... &   # A 宇宙
claude -p "生成文件" ... &   # B 宇宙
wait                         # 等兩個平行宇宙都做完
```

> 在 A 宇宙的資料夾，AI 專心掃資安；B 宇宙的資料夾，另一個 AI 瘋狂寫檔案。因為硬碟上是分開的兩個地方，**絕不會碰到彼此的檔案**。做完再把結果合併回主宇宙——避開了 merge 衝突的噩夢，也大幅縮短流程時間。

# 結語：AI 從「工具」升級為 pipeline 的「自主節點」

我們走過一條完整的 AI 工程化道路：

| 階段 | 機制 |
|------|------|
| 讓它閉嘴 | headless `-p` |
| 講機器話 | JSON metadata（`is_error`/`cost`/`session_id`）|
| 戴上護欄 | 白名單 + 回合 + 預算三防爆衝 |
| 不會翻車 | plan mode 硬限制 + 只開 PR + SKIP ACTIONS |
| 能夠協作 | session 延續 + worktree 平行宇宙 |

## 留給你的思想實驗 🤔

今天我們看到 AI 如何從「開發者的小幫手」，演變成「自動化 pipeline 中的自主代理人（Agent）」。如果連 debug、測試、開 PR、寫文件都能交給這群不知疲倦的代理人——

> 軟體工程師的核心價值，或許會發生根本性轉變：
> 從**親手一行一行敲程式碼**，
> 轉變成**設計嚴謹的系統護欄、編排 AI 代理人網路的管理者**。
>
> 就像從一個在工地砌磚的工人，變成在藍圖上規劃「多台自動化怪手如何協同作業」的總工程師。

當你的 pipeline 裡有一半以上的貢獻者都不是人類時，我們該如何重新定義「團隊合作」？這是留給所有人思考的問題。
